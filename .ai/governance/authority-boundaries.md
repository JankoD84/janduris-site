# Authority Boundaries

## Site Content Authority vs Domain Authority

`app/content.ts` is the implementation source for much of what this site displays. It is not automatically the canonical source of truth for:

- Dulvarn architecture or product state
- Dulvarn Tools capabilities or commercial status
- Wildcode infrastructure
- agent-system architecture
- release-decision semantics outside this portfolio
- external provider state
- employment records outside approved site content
- live deployment state or provider configuration

SITE CONTENT AUTHORITY != ECOSYSTEM DOMAIN AUTHORITY.

## Source Rules

For repository-verifiable facts, use current repository files.
For personal claims, use current approved site content, owner-provided facts, or authoritative owner-supplied sources.
For external project claims, use the canonical project source or explicit owner confirmation.

Do not use stale README text, private AI memory, generated docs, or old conversation context as authoritative without verification.

## Public Publishing Boundary

This repository is public. Treat every committed value as globally visible and persistent. Do not add private context, secrets, account identifiers, private URLs, or personal data not explicitly approved for publication.
